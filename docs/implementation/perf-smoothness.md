# Performance & smoothness pass — working plan (2026-10-19)

Branch: `perf/smoothness`. Basis: three-part read-only audit (interaction jank, chart load, backend memory) performed 2026-10-19; findings reference exact files/lines below.

**Goal:** the app feels immediate and fluid ("oh, what a smooth app") without sacrificing the visual language. Memory wins where they are real; budgets stay green (current headroom: CSS 45 B, dashboard JS 193 B gzip — keep changes size-neutral; landing JS has ~60 KB headroom).

**Invariants:** motion guide durations (160–240 ms UI, 650 ms reveal); GEMINI.md metric/quality-gate rules untouched; API serves snapshots and never runs pipeline work inline; no new dependencies.

### H — Heatmap hover card (post-pass bug report, 2026-10-20)
- [x] H1 The hover card (`HeatmapCategoryPanel`, `position: fixed`) was positioned against the map rect captured at hover time, and its lifetime was driven only by pointer boundary events. Scrolling the page under a stationary pointer left it floating over unrelated sections (the report's screenshot: over the news panel) — for a few hundred ms when Chrome's scroll-born `pointerout` reached the 180 ms close grace, indefinitely when no boundary event arrived; a later jiggle re-clamped it against the stale rect. Fix: `HeatmapTreemap` invalidates hover on any scroll that can move the map (window `scroll` in the capture phase; scrollers that do not contain the map, such as the pinned peer list, are ignored), clears its refs/highlight and calls `onHoverInvalidated`, which closes the hover card synchronously in `HeatmapPanel` (no 180 ms ghost). Scroll-born boundary events are ignored for 200 ms (mouse/pen only, so touch taps still open), and the first genuine `pointermove` after a scroll re-resolves the cell under the pointer even when it never left that tile. Pinned cards are a deliberate, dismissible state and stay put.
