# CopperMind Modeling, Quality Gate & Database Contracts

These guidelines capture the core mathematical, operational, and database contracts for CopperMind while preserving full engineering autonomy over implementation and optimization.

## 1. Financial Metric Contracts & Lookahead Safeguards
- **Annualization & Horizon Matching:** Match annualization factors in `sharpe_ratio` and `sortino_ratio` to the target horizon:
  - **Daily ($T+1$) single-step returns:** Scale by $\sqrt{252}$.
  - **Weekly (5-day) cumulative returns:** Scale by the codebase convention $\sqrt{52}$ (approximating $\sqrt{252 / 5} \approx 7.10$ non-overlapping 5-day trading blocks per year). Never annualize 5-day cumulative returns with $\sqrt{252}$.
- **Overlapping Horizon Autocorrelation:** Daily-sampled 5-day cumulative returns ($R_{t \to t+5}$) overlap by 4 trading days and exhibit $\text{MA}(4)$ serial correlation. Unadjusted sample Sharpe/Sortino on daily sliding windows reflects overlapping observations; quality gates, `run_backtest(..., use_hac=True)`, and `theta_backtest(..., return_mode="cumulative", use_log_return=True, annualisation=52.0)` use Newey-West HAC variance adjustment (`sharpe_ratio_hac`).
- **Causal & Stationary Feature Boundaries:** Filter weekend (`dayofweek >= 5`) ghost futures bars across price ingestion (`ingest_prices`), price loading (`_rows_to_price_df`), feature store (`build_tft_dataframe`), and DB cleanup (`dedup_price_bars.py`). Compute rolling regime, trend (`close / SMA_w - 1`), signed risk-adjusted momentum (`risk_adj_ret*`, `signed_vol_ratio`), causal Ridge `macro_fair_value_zscore`, causal `HG=F_theta_5d_prior`, and volatility features exclusively from historical observed returns (`observed_return_1d`) and scale-invariant ratios (`include_raw_ma=False` in TFT including `ret10`, excluding unsigned `*_vol_*` from TFT encoder inputs while keeping `realized_vol_20d` solely for Split CQR), never raw unnormalized price levels (`SMA_5`, `symbol / target`) or forward-looking targets. Keep `TimeSeriesDataSet`'s daily target strictly causal (`target = log_close.diff()`) so decoded steps `[t+1..t+5]` sum to `target_5d_log_return[t]` without a 1-day double-shift, disable constant static bias channels (`add_target_scales=False`, `add_encoder_length=False`, `add_relative_time_idx=False`), restrict known future calendar covariates to Mon–Fri normalized `day_of_week = clip(dayofweek, 0, 4) / 4.0` (`{0.0, 0.25, 0.50, 0.75, 1.0}`, excluding annual date/month features from both `known` and MRMR), decouple live news/FinBERT DB queries from TFT training by default (`include_news_features=False`, keeping sentiment/FinBERT in the post-model commentary & risk layer), and fit sub-period sign-consistent hybrid `|Spearman| + MI` budget-capped MRMR feature selection with per-group diversity cap (`max_per_group=2`, seeded with the balanced 5-signal core `HG=F_ret5`, `HG=F_close_sma_20_ratio`, `HG=F_signed_vol_ratio`, `HG=F_theta_5d_prior`, `macro_fair_value_zscore`, zero-variance `< 1e-8` and sparse `< 8%` coverage pruning, `mrmr_top_k=12`) strictly on the training partition with fresher chronological splits (`val_ratio=0.08`, `test_ratio=0.10`).

## 2. Weekly Quantile Aggregation, Loss Scaling & Split CQR
- **RSS Weekly Quantiles (`monotonic_quantiles.py`):** Aggregate 5-day quantile horizons with additive medians ($\sum_h q_{50,h}$) and root-sum-of-squares (L2) quantile half-widths ($\sqrt{\sum_h d_{h,q}^2}$), preserving monotonicity without assuming perfect daily comonotonicity.
- **Scale-Normalized Demeaned `WeeklyASROPFLoss`, 3-Seed Ensemble & Hybrid Blend:** Override `Metric.update()` so `val_loss` and backprop losses equal raw batch loss without `MultiHorizonMetric` `B * H` dilution; keep `t1_q_loss` on the same `_pinball` scale as `weekly_q_loss` (`lambda_t1_quantile=0.20`); use batch-demeaned directional utility (`lambda_directional=0.10` default, search `[0.05, 0.10, 0.15]`) with L1+L2 zero-drift prior (`|mean|/scale + (mean/scale)^2`, `lambda_drift_prior=4.0` default, search `[2.5, 4.0, 6.0]`, `lambda_bias=0.0`) normalized by `WeeklyTargetScale`; train compact 3-seed ensembles (`ensemble_seeds=(42, 137, 256)`, `allow_soup=True` on all seeds, `hidden_size=12`, `hidden_continuous_size=6`, `attention_head_size=1`, `max_encoder_length=15`, `dropout=0.30`) with `AdamW` + decoupled output-head learning rates (`learning_rate=5e-4`, `output_head_lr_mult=0.20` for weights vs. `0.05x` cap for biases, `weight_decay=1.5e-2`), filtering ensemble members strictly on validation skill/loss and train/val drift bounds (`val_mae_vs_naive <= 0.99`, `val_loss <= 1.05 * best`, `|val_pred_mean| <= 0.0025`, `|train_pred_mean| <= 0.005`) without subtracting `val_pred_mean`, keeping legacy heuristic regularizers disabled (`0.0`).
- **Validation Hybrid Blend & Split CQR Post-Hoc Calibration:** Fit a validation-only convex `w_tft * TFT + w_theta * Theta` median blend (`fit_theta_hybrid_blend`, `w_tft >= 0.35`, enforcing a structural `min_theta_weight=0.25` regime-insurance floor when Theta shows validation edge without material MAE degradation) followed by linear-volatility Split CQR (`fit_weekly_cqr`, `base_vol_power=1.0`) on validation residuals only and apply symmetrically (`apply_theta_hybrid_shift_to_path`, `apply_weekly_cqr`) to test evaluation, `TFTBacktestRunner` (tracking separate `strict_oos` post-validation windows), and live inference while keeping quantiles strictly non-crossing.

## 3. Quality Gate & Promotion Isolation
- **Primary Weekly Gate (`backend/app/quality_gate.py`):** Enforce structural monotonicity (`quantile_crossing_rate == 0`, `median_sort_gap <= 1e-4`), prevent trivial collapse (`weekly_magnitude_ratio >= 0.02`, no artificial `0.65` floor on Bayes-optimal noisy returns) and over-scaling (`<= 2.50`, `weekly_raw_magnitude_ratio <= 3.0`), cap `weekly_mae_vs_naive_zero <= 1.12`, apply sample-size-aware binomial PI80 coverage bounds around 80%, require HAC `weekly_sharpe_ratio >= -0.35`, and gate weekly directional accuracy by sample size (`>= 0.45` for `n < 150`, `>= 0.47` for `150 <= n < 300`, `>= 0.49` otherwise). T+1 `sharpe_ratio`, `tail_capture_rate`, and variance ratio serve as non-blocking diagnostic warnings on weekly-primary TFT models.
- **Strict Promotion & Revision Sync:** Active model serving endpoints and snapshot invalidation filter `quality_gate_passed.is_(True)`. Candidate training never overwrites active serving rows; active metadata commits only after gate + HF Hub upload pass, and live/backtest workers call `sync_tft_artifacts_if_stale` (tracking `.hf_revision` + resetting cached predictor) before inference.

## 4. Horizon Consistency, Backtesting & Explainability
- **Primary vs. Diagnostic Separation:** Keep primary 5-day cumulative weekly forecasts (TFT-ASRO) distinct from single-step $T+1$ daily diagnostics (XGBoost) in API schemas and UI views.
- **Zero-Lookahead Backtests:** XGBoost Champion/Challenger backtests predict $T+1$ simple returns with `target_date <= train_end` cutoff, short-circuit matching `content_hash` sets (`KEEP_CHAMPION`), and test significance via paired block-bootstrap 95% CI. TFT backtests evaluate real promoted checkpoints (`TFTBacktestRunner`) against horizon-matched cumulative log-return Theta baselines with no moving-average stubs.
- **Explainability Contract:** TFT-ASRO explanations (`explain_json`, served by `/api/explain/{symbol}`) are optional, fail-open worker artifacts representing raw, pre-calibration 5-day model focus (VSN weights + encoder-window attention), never causal attribution.

## 5. Database & Connection Pooler Contracts
- **Dialect Explicit Binding & Fallback:** Dynamically normalize unspecified `postgresql://` URIs in `backend/app/db.py` to the installed driver (`postgresql+psycopg://` or `postgresql+psycopg2://`).
- **Transaction Pooler vs. Direct Connection Prepared Statements:**
  - When connecting through **transaction-mode connection poolers** (`:6543`, `pooler.supabase.com`, `pgbouncer`) with `psycopg` v3, disable prepared statements via `connect_args={"prepare_threshold": None}` to prevent `DuplicatePreparedStatement` / `InvalidSqlStatementName` errors.
  - On **direct PostgreSQL / session-mode connections** (e.g., port `:5432` on `db.<project>.supabase.co` without pooler host/port markers), leave `psycopg` prepared statements enabled so repeated queries benefit from server-side statement caching.
